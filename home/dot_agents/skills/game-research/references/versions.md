# Version Research

Determine whether a specific game deserves play and which release and playing
setup best serve the user. Ask which game only if missing; disambiguate same-name
games when needed.

## Discover the candidates

Account for the original release and major arcade, console, handheld, and computer
adaptations, including older computer versions where relevant. Consider modern
rereleases, remasters, remakes, compilations, source releases, source ports,
decompilation-based ports, static recompilations, engine reimplementations, fan
remakes, and useful translations or patches. Consult source guidance for current
discovery leads, then verify upstream projects and specific releases.

Do not exclude a version from consideration because it lacks two recommendations.
The platform mode's threshold does not apply. Group minor variants with reasons;
identify known major omissions and unknowns. A decompilation percentage or a
recompilation announcement does not prove an end-user release exists.

## Compare practical setups

Assess whether the game itself remains enjoyable before choosing its best port.
Then compare materially relevant setups using the shared readiness check. Track
the release/region, implementation or emulator, host, and required patches or
data separately. Verify operating system and architecture support rather than
inferring Android support from a Linux release or compatibility from another game.

Preserve differences in content, mechanics, graphics, music and sound hardware,
input, localization, censorship, saving, loading, performance, bugs, and fidelity.
Distinguish remakes that reinterpret the game from releases preserving it.

Compare emulation benefits such as save states, rewind, and suspend/resume against
native-port benefits such as improved controls, performance, and optional features
where supported. Verify reliability rather than assuming feature parity. Consider
interpreters and compatibility layers, including DOSBox, ScummVM, or DREAMM when
relevant, without assuming any particular title is supported.

Recommend an overall default only when evidence supports it. If preferences or
uncertain readiness prevent a single winner, give conditional recommendations and
the unresolved question instead of manufacturing a definitive edition.

## Output

Lead with whether the game is worthwhile and the preferred first-play setup, or
why a conditional choice is necessary. Provide this ranked comparison:

| Rank | Exact version and implementation/setup | Best for | Main trade-off | Readiness and evidence |
|---:|---|---|---|---|

Include alternatives only for meaningful differences, such as authentic original
experience, convenience, handheld controls, enhanced source ports, or unique
content. Mark experimental or insufficiently evidenced projects accordingly.

Summarize each major candidate's included content, changes, strengths, weaknesses,
and recommendation status; group uncompetitive minor variants. Add a coverage
matrix when content overlap matters. Explicitly identify replacements, partial
overlap, and unique experiences rather than assuming remakes contain everything.

End with concise setup requirements, current access constraints, versions to avoid
with reasons, citations, research date, and unresolved gaps. Provide enough setup
detail to choose a path; do not turn research into installation work or download
and run projects unless separately requested.
